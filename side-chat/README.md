# 侧边栏会话（Side Chat）

在 DSH Web GUI 里输入 `/`，选「侧边栏会话」，就能在当前对话旁边开一段临时旁支对话。交互参照 OpenAI Codex 的 `/side`：继承主对话上下文、侧栏里不出现主对话历史、关掉标签后丢弃。

当前是**原生输入框模式**：侧栏里用的是 DSH 自带的输入框，所以模型切换、粘贴图片、`/` 命令、`@` 引用都能用。代价是使用期间左侧会话列表的“未分组”里会出现这一行；关掉标签时自动归档，那一行随即消失（归档页里还能找到）。

## 用法

1. 在任意有已完成轮次的主对话里输入 `/`。
2. 选「侧边栏会话」。
3. 右侧栏出现一个临时对话，用原生输入框提问（模型切换、贴图、`/`、`@` 都可）。
4. 关闭该标签页：侧栏消失、“未分组”里的那一行被归档隐藏；再次 `/` 会开一段全新的。

一个主对话同时只有一段侧栏对话：已经开着时再选 `/` 只会聚焦到同一个标签。侧栏对话里不再提供 `/side`。

## 为什么不是“完全无痕 + 原生输入框”

DSH 里“不出现在任何列表”的开关只有 `origin=subagent`（见 `ui-workspace` 的 `sessionVisible`），但这类会话被硬编码禁用原生输入框提交、模型选择器和命令目录；归档能隐藏会话，却会拦住 `agent/pre-step`，会话就不能跑模型。三条限制互斥，所以只能在“原生能力”和“完全无痕”之间取舍，本插件选了原生能力。

## 实现方式

- **临时会话**：Client 用 `ctx.sessions.create({ cwd, agentPreset })` 建一个不归属任何 workspace 的普通会话（因此只在“未分组”出现），并继承主对话的模型/预设。
- **侧栏渲染**：Client 用自建 resource 协议 + 侧栏 tab 类型渲染这段会话，`sessions.retain(sessionId)` 后走标准 Conversation，**输入框就是 DSH 原生的**。
- **上下文继承**：Host 用私有通道 `/side-chat` 给这段会话的 Agent 注册一个隐藏的 prompt context（`side-chat:context`），每次请求时重新读取主对话最近记录（最多约 80 条事件、1.2 万字），以背景形式参与请求；不写入侧栏聊天记录，也不堆叠历史副本。
- **关闭即丢弃**：关闭标签时 Client 先解绑上下文，再归档并停止活动；再次 `/` 是新会话。打开（含刷新后恢复标签）时会先取消归档再重绑上下文。

## 已知限制

- 使用期间左侧“未分组”会有一行；关闭后归档隐藏，但归档页里仍可见、会话日志仍在磁盘上（DSH 没有删除会话的 Host API）。
- 关闭时的归档会走 DSH 的归档语义；如果你从“归档”页手动打开该会话，它不会再回到侧栏 tab 形态。
- 依赖几个内部接口：`ctx.sessions.create({ cwd })` 的“未归属 workspace”行为、`conversation.composer.bar` 之外的自有后端通道、`systemPrompt.context` 的 per-Agent 作用域、侧栏 resource/tab 注册、以及 `ctx.get` 取服务的请求路径约束。DSH 升级后可能需要调整。
- Host 的 HTTP 路由处理器里**不能**用 `ctx.<service>` 属性访问（必须 `ctx.get(...)`），且任何异常都必须在处理器内部捕获：在 Web 路由里抛错会被 DSH 当成致命错误直接退出进程（我们踩过，两次闪退就是这个）。

## 安装

```bash
# 在 DSH 插件管理器里把本目录作为 workspace bundle 安装
plugin_manager install_bundle /path/to/dsh-plugins/side-chat
```
