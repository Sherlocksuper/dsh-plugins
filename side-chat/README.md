# 侧聊（Side Chat）

在 DeepSeek Harness Web GUI 中创建临时侧聊，行为对齐 Codex 桌面版的普通临时 Side chat。依赖 DSH **0.2.1-rc.3**。

## 使用

- 在主聊输入 `/side`，或在标题栏“更多操作”菜单中选择“新建侧聊”。
- 右侧栏的“新建标签”页也提供“新建侧聊”入口。
- 每次新建都是独立侧聊，允许同时打开多个，标题按“侧聊”“侧聊 2”编号。
- 仍使用原生输入框，支持模型选择、图片、文件、`@` 引用及原生队列和停止操作。
- 桌面版默认快捷键与 Codex 一致：macOS 为 `⌘⌥S`，Windows/Linux 为 `Ctrl+Alt+S`。浏览器版 macOS/Windows 使用同一组合；Linux Web 按 DSH 的浏览器限制不设默认键，可在设置中选择宿主支持的组合。

侧聊继承**创建时**的主聊历史、工作目录、模型、推理等级和权限。继承的历史只用于理解背景，不出现在侧聊聊天区。主聊之后的新消息不会自动同步，侧聊答案也不会自动回传主聊。侧聊内不提供再次创建侧聊的命令。

## 临时会话与关闭

侧聊只在内存中运行，没有持久化写入句柄，不产生侧聊 JSONL，不进入普通会话列表、搜索结果或归档列表。关闭标签或退出应用会停止侧聊并释放会话，无法找回。收起侧栏、切标签和切主聊会保留仍打开的侧聊。

有内容时关闭会弹出确认，可选择“不再询问”。后端停止及释放成功后才关闭标签；失败保留标签和错误信息，可再次尝试。创建中的标签可取消，取消后不会在后台遗留侧聊。过期标签只显示新建入口，不把它当作可恢复的正式会话。

侧聊允许轻量检查。修改工作区必须由侧聊用户明确要求；禁止创建或操作子智能体，禁止为临时侧聊建立 worktree 或安排长期任务。聊天分叉不会隔离文件，主聊和侧聊仍可能使用同一目录。

## 实现与版本边界

- `runtime.js` 复用 DSH 的原生 fork 逻辑，保留图片、工具调用/结果、有效压缩历史，并修复创建时仍未结束的工具调用。
- 通过 AgentLoop 的原生发布事务创建 Agent，但不申请持久化句柄。没有“先落盘再删除”或“关闭后归档”的替代路径。
- DSH 当前没有临时侧聊的列表扩展点。适配器为侧聊的**新增导航摘要**使用宿主现有隐藏标记，并省略子智能体地址；历史列表、查询和搜索结果排除这些临时身份。真实 Session header 和原生输入路由不改为子智能体。客户端从认证后的身份直接建立作用域，不依赖普通会话列表。插件卸载会恢复这些适配方法。
- 一个浏览器窗口共享一条生命周期连接，避免多标签占满 HTTP 连接池。页面连接消失会释放该窗口持有的侧聊，单标签释放不影响其他侧聊。
- 主聊规则继续由 DSH 加载；`prompts/AGENTS.md` 是插件显式安装到侧聊的独立规则，不修改项目规则。
- `agentLoop.setupAndPublish`、导航摘要、侧栏席位和 `data-chat-turn` 是当前版本内部接口。DSH 升级需要重新验收。

## 安装与升级

在 DSH 插件管理器中，将本目录作为 workspace bundle 安装：

```text
plugin_manager install_bundle /absolute/path/to/dsh-plugins/side-chat
```

从 1.x 升级前结束旧侧聊。旧版本留下的持久会话继续保留，本插件不删除用户已有记录，也不将它们伪装成新的临时侧聊。

## 验证

```bash
npm run check
DSH_RUNTIME_ROOT=/path/to/unpacked/dsh npm test
```

运行时目录须包含完整的 `node_modules/@deepseek-ai`。集成检查使用真实 DSH Agent、Session、工具和 JSONL 后端，本地模型替身不请求外部模型。没有提供运行时路径时会明确跳过集成项，不能据此宣称通过实机验收。
