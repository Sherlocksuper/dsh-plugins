# 侧边栏会话（Side Chat）

在 DSH Web GUI 里输入 `/`，选「侧边栏会话」，就能在当前对话旁边开一段临时旁支对话。创建时分叉主聊已有历史，之后在每次侧聊提问前同步主聊新增记录。侧栏只展示侧聊内容，关闭标签后归档。

当前是**原生输入框模式**：侧栏里用的是 DSH 自带的输入框，所以模型切换、粘贴图片、`/` 命令、`@` 引用都能用。代价是使用期间左侧会话列表的“未分组”里会出现这一行；关掉标签时自动归档，那一行随即消失（归档页里还能找到）。

## 用法

1. 在主对话里输入 `/`。
2. 选「侧边栏会话」。
3. 右侧栏出现一个临时对话，用原生输入框提问（模型切换、贴图、`/`、`@` 都可）。主聊继续工作后，再向侧聊提问会自动补入新增背景。
4. 关闭该标签页：侧栏消失、“未分组”里的那一行被归档隐藏；再次 `/` 会开一段全新的。

一个主对话同时只有一段侧栏对话：已经开着时再选 `/` 只会聚焦到同一个标签。侧栏对话里不再提供 `/side`。

## 为什么不是“完全无痕 + 原生输入框”

DSH 里“不出现在任何列表”的开关只有 `origin=subagent`（见 `ui-workspace` 的 `sessionVisible`），但这类会话被硬编码禁用原生输入框提交、模型选择器和命令目录；归档能隐藏会话，却会拦住 `agent/pre-step`，会话就不能跑模型。三条限制互斥，所以只能在“原生能力”和“完全无痕”之间取舍，本插件选了原生能力。

## 实现方式

- **初始分叉**：Host 通过 `ctx.agents.create({ seed, inheritedEventCount, meta, agentOptions, setup })` 建立普通会话，复制主聊截至最近一个 `turn/end` 的原生日志，保留原始消息角色、工具调用/结果、图片和压缩状态。尚无完整轮次时从空分叉开始，在首次侧聊提问前同步可用记录。清空继承的待发送队列，防止侧聊自动执行主聊任务。会话不归属 workspace，保持“未分组”行为。
- **侧栏渲染**：保留 resource/tab 和 `sessions.retain(sessionId)` 的标准 Conversation，**输入框仍是 DSH 原生的**。仅在对应侧栏内按 DSH 的 `data-chat-turn` 属性隐藏继承轮次，不改变模型历史或主聊显示。
- **增量同步**：作用于侧聊 Agent 的 `agent/pre-step` 监听器在有侧聊用户输入时读取主聊的有效消息，按已提交的父事件游标追加尚未同步的内容。完整文字和工具调用/结果以带原始角色、消息 ID 和来源的隐藏背景消息记录，避免把主聊工具调用当成侧聊待执行调用；图片和文件保留原生内容块。主聊 system prompt、runtime-context 和供应商私有 replay state 不作为新增背景复制。移除了单条 1,200 字符、总量 12,000 字符的截断。
- **同步边界**：尚未收到全部结果的工具调用组会暂缓，之前完整的消息仍可同步；工具组完整后，在下一次侧聊提问时补入。侧聊自动调用工具的后续步骤不会反复同步主聊，也不会因为主聊更新而自行唤醒。
- **提交与恢复**：只有隐藏同步消息实际进入侧聊日志后才推进游标；重试、刷新、Agent 重新加载时，从自己的日志恢复游标，避免重复同步或跳过未提交内容。主聊读取失败会阻止本轮模型请求，并把用户问题保留在待发送队列；恢复后可重新发送队列问题。
- **关闭与归档**：关闭标签时解除侧聊规则和同步监听，再归档并停止活动；再次 `/side` 创建新分叉。恢复侧栏时会取消归档、必要时恢复 Agent，再安装规则和同步监听。上下文安装失败时显示错误，不开放缺少上下文的输入框。

## 侧聊规则与提示词

`prompts/AGENTS.md` 由 Host 显式读取，作为仅作用于侧聊的固定 system prompt section 安装，不修改项目的 `AGENTS.md`。它规定侧聊只处理侧聊用户的请求，主聊历史中的任务和授权用于理解背景，不自动触发执行。项目原有指令继续由 DSH 按工作目录加载。

增量背景的提示词在 `context.js` 中生成，标明父会话、同步事件范围、每条消息的原始角色和来源，并明确这些记录属于主聊。新增背景追加到侧聊历史末尾，不再每轮改写前面的整份主聊摘要。侧聊答案不会自动回传主聊。

## 已知限制

- 使用期间左侧“未分组”会有一行；关闭后归档隐藏，但归档页里仍可见、会话日志仍在磁盘上（DSH 没有删除会话的 Host API）。
- 主聊和侧聊共用工作目录，分叉不隔离文件修改。未实际读取的路径不会自动变成文件内容；附件能否被模型读取仍受所选模型、DSH 附件服务及原始文件可用性约束。
- 分叉和同步继承的是 DSH 当前有效历史，不能恢复压缩时已丢弃的原文。没有人为字符截断后，大量同步内容仍会消耗上下文窗口和输入 token，由 DSH 自身的压缩与模型限制处理。
- 1.0 的旧侧聊不是原生分叉，不能直接续用这套游标；升级前关闭旧侧聊，升级后重新 `/side`。旧标签恢复时会明确提示重新打开，不会悄悄作为无上下文侧聊运行。
- 关闭时的归档会走 DSH 的归档语义；如果你从“归档”页手动打开该会话，它不会再回到侧栏 tab 形态。
- 依赖 DSH 0.2.1-rc.3 的内部接口：带 seed 的 Agent 创建、`sessionQuery.observeSession`、Session 的模型消息投影、`agent/pre-step`、`systemPrompt.section` 的 per-Agent 作用域、侧栏 resource/tab 注册和 `data-chat-turn` 显示属性。DSH 升级后可能需要调整。
- Host 的 HTTP 路由处理器里**不能**用 `ctx.<service>` 属性访问（必须 `ctx.get(...)`），且任何异常都必须在处理器内部捕获：在 Web 路由里抛错会被 DSH 当成致命错误直接退出进程（我们踩过，两次闪退就是这个）。

## 安装

```bash
# 在 DSH 插件管理器里把本目录作为 workspace bundle 安装
plugin_manager install_bundle /path/to/dsh-plugins/side-chat
```

## 验证

在 `side-chat` 目录运行 `npm run check` 和 `npm test`；单元检查无需安装依赖，覆盖长文本、附件、工具组边界、游标恢复、重复打开及上下文安装失败。

若有解包后的 DSH 0.2.1-rc.3 运行时（目录下含 `node_modules/@deepseek-ai`），运行以下命令同时执行集成检查：

```bash
DSH_RUNTIME_ROOT=/path/to/unpacked/dsh npm test
```

集成检查使用真实 DSH 会话、Agent 循环和临时 JSONL 存储，模型由本地测试替身提供，不调用模型 API。覆盖真实请求中的分叉历史、增量与规则、刷新和冷恢复、同步失败保留问题及并发打开。不提供运行时路径时，该项会明确跳过。这不替代 DSH GUI 实机验收。
